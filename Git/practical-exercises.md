
# 💻 Git — Practical Exercises

### Technical Writing Laboratory | MNIT Jaipur

> **Learn by doing. Track every change. Verify every result.**

This document contains practical exercises demonstrating essential Git commands, repository management, commits, branches, merging, and remote operations.

All exercises should be performed using Git Bash or a compatible terminal.

---

## 🎯 Objectives

- Verify Git installation and configuration.
- Initialize and manage a local repository.
- Create, modify, stage, and commit files.
- Inspect commit history and file differences.
- Create and merge branches.
- Connect a repository to GitHub.
- Demonstrate remote repository operations.

---

Run exercises in order. Press `q` if a history view opens a pager. Stop and inspect any unexpected error before continuing.

## 🛠️ Prerequisites

- Git installed
- Git Bash or terminal
- Text editor or VS Code
- GitHub account for remote exercises
- Internet connection for GitHub operations

**Important:** Perform these exercises in a separate `tw-git-exercises` directory rather than directly modifying the main Technical Writing repository.

## 🔥 Exercise 1 — Verify Git Installation

**Aim:** Verify that Git is installed and accessible.

### Command

```bash
git --version
```

### Expected Result

The terminal displays the installed Git version.

```text
git version X.Y.Z
```

The exact version depends on the installation.

**Screenshot:** `01-git-version.png`

## 🔥 Exercise 2 — Create a Practice Repository

**Aim:** Start in a new folder so your existing coursework is unaffected.

Run these commands once. If the folder already exists, choose a new name.

```bash
mkdir tw-git-exercises
cd tw-git-exercises
git init -b main
git status
```

**Expected result:** You are on `main`, with no commits yet. Git stores history in `.git`.

**Screenshot:** `02-git-init-status.png`

## 🔥 Exercise 3 — Set the Commit Author

Replace both example values with your own details before running:

```bash
git config user.name "Your Name"
git config user.email "your-email@example.com"
git config user.name
git config user.email
```

**Expected result:** Your chosen name and email appear. These settings apply only to this practice repository.

**Understand:** Commit identity is separate from GitHub login. Use an email associated with your GitHub account if you want commits attributed to that account.

## 🔥 Exercise 4 — Create, Stage, and Commit a File

**Aim:** Track a file and create the first commit.

### Commands

```bash
echo "# Git Practice" > README.md
git status
git add README.md
git status
git commit -m "Initial commit"
```

### Expected Result

- The new file initially appears as untracked.
- After staging, it appears under changes to be committed.
- The commit records the staged file.

### Verification

```bash
git status
git log --oneline
```

**Observation:** Git records staged changes as commits.

**Screenshot:** `03-git-add-commit.png`

## 🔥 Exercise 5 — Modify a File and Inspect Differences

**Aim:** Demonstrate change detection and comparison.

### Commands

```bash
echo "Learning Git version control." >> README.md
git status
git diff
```

Stage the changes:

```bash
git add README.md
git diff --staged
```

Commit:

```bash
git commit -m "Update Git documentation"
```

### Expected Result

`git diff` displays unstaged modifications, while `git diff --staged` displays staged modifications.

**Observation:** Git allows users to inspect changes before committing them.

## 🔥 Exercise 6 — Inspect Commit History

**Aim:** View the repository's recorded revisions.

### Commands

```bash
git log
git log --oneline
git log --oneline --graph --all
```

### Expected Result

The terminal displays the commits created in previous exercises.

### Example Format

```text
<hash> Update Git documentation
<hash> Initial commit
```

Commit hashes are generated by Git and vary between repositories.

**Screenshot:** `04-git-log.png`

## 🔥 Exercise 7 — Create and Switch Branches

**Aim:** Demonstrate independent development using branches.

### Commands

```bash
git switch -c feature-docs
git branch
```

Modify the README:

```bash
echo "This line was added on the feature branch." >> README.md
git add README.md
git commit -m "Add feature branch content"
```

### Expected Result

A new branch named `feature-docs` is created and checked out.

The commit is recorded on that branch.

**Observation:** Branches allow changes to be developed independently.

---

## 🔥 Exercise 8 — Merge Branches

**Aim:** Integrate changes from the feature branch.

### Commands

Switch to the branch that should receive the changes:

```bash
git switch main
```

Merge the feature branch:

```bash
git merge feature-docs
```

Verify:

```bash
git log --oneline --graph --all
git status
```

### Expected Result

Changes from `feature-docs` become part of the current branch.

Because the branches have not diverged in this exercise, Git will normally perform a fast-forward merge.

### Optional Cleanup

```bash
git branch -d feature-docs
```

**Observation:** Merging integrates work developed on separate branches.

**Screenshot:** `05-git-branch-merge.png`

## 🟡 Exercise 9 — Connect to a GitHub Repository

**Aim:** Link a local repository to a remote GitHub repository.

### Step 1: Create a Remote Repository

Create a new empty repository on GitHub named:

`tw-git-exercises`

Do not initialize it with a README, license, or `.gitignore`, because the local repository already contains commits.

### Step 2: Check Current Branch

```bash
git branch --show-current
```

### Step 3: Rename Branch to Main

```bash
git branch -M main
```

### Step 4: Add Remote

```bash
git remote add origin https://github.com/YOUR-USERNAME/tw-git-exercises.git
```

Replace `YOUR-USERNAME` with your GitHub username.

### Step 5: Verify Remote

```bash
git remote -v
```

### Step 6: Push Commits

```bash
git push -u origin main
```

### Expected Result

The local `main` branch is uploaded to GitHub, assuming authentication and permissions are configured.

**Observation:** GitHub can host and share the repository's commit history.

**Screenshot:** `06-git-remote-push.png`

## 🟡 Exercise 10 — Clone and Fetch

**Aim:** Demonstrate copying a remote repository and retrieving updates.

Return to the parent directory:

```bash
cd ..
```

Clone the GitHub repository into a different folder:

```bash
git clone https://github.com/YOUR-USERNAME/tw-git-exercises.git tw-git-exercises-clone
```

Enter the cloned repository:

```bash
cd tw-git-exercises-clone
```

Inspect the remote:

```bash
git remote -v
```

Fetch updates:

```bash
git fetch origin
```

### Expected Result

A local clone is created and its remote configuration can be inspected.

**Observation:** Cloning creates a local repository from a remote source, while fetching retrieves available remote updates.

---

## 🟡 Exercise 11 — Demonstrate Git Restore

**Aim:** Restore a file after an unwanted local modification.

Inside the cloned repository:

```bash
echo "Temporary change" >> README.md
git diff
```

Discard the unstaged change:

```bash
git restore README.md
git status
```

### Expected Result

The temporary modification is discarded and the working tree returns to its previous state.

**Warning:** `git restore README.md` can permanently discard unstaged changes.

## 🔎 Practical Observations

- Git initializes local repositories for version control.
- Staging selects changes for the next commit.
- Commits record project revisions.
- History commands display previous commits.
- Branching supports independent development.
- Merging integrates branch changes.
- Remote repositories allow project synchronization.
- Restore commands help manage unwanted modifications.

## 🔀 Additional Practice — Resolve a Merge Conflict

Run this inside `tw-git-exercises` on `main`, with a clean working tree, after Exercise 8. Both branches deliberately change the same line in a disposable file.

```bash
echo "Mode: original" > conflict.txt
git add conflict.txt
git commit -m "Add conflict example"
git switch -c conflict-demo
echo "Mode: feature" > conflict.txt
git add conflict.txt
git commit -m "Change mode on feature branch"
git switch main
echo "Mode: main" > conflict.txt
git add conflict.txt
git commit -m "Change mode on main branch"
git merge conflict-demo
```

**Expected result:** The last command reports a content conflict. That is intentional here. Inspect it:

```bash
git status
cat conflict.txt
```

The file contains `<<<<<<<`, `=======`, and `>>>>>>>` markers around the competing versions. Save a screenshot before resolving it. For this example, replace the entire disposable file with an agreed result:

```bash
echo "Mode: combined" > conflict.txt
git add conflict.txt
git commit -m "Resolve mode conflict"
git log --oneline --graph --all
git status
git branch -d conflict-demo
```

**Expected result:** A merge commit joins the histories and the working tree is clean. In real work, review and edit each conflict rather than overwriting an entire file.

## 🧠 Quick Viva Check

| Question | Answer |
| :--- | :--- |
| What does staging do? | Selects content for the next commit. |
| Does commit upload files? | No. A commit is local; push sends commits to a remote. |
| Why was the first merge a fast-forward? | Main had no independent commits after the branch split. |
| Why did the conflict occur? | Both branches changed the same line differently. |
| Does Git configuration sign you into GitHub? | No. It sets commit metadata, not authentication. |
| Fetch versus pull? | Fetch downloads updates; pull also integrates them. |
